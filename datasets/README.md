# Dataset acquisition

The current acquisition/merge workflow is documented in the repository-root `train_colab.ipynb` notebook. Open it in Google Colab and execute it from top to bottom. It requests a Roboflow API key, downloads the public fastener datasets, maps the annotations to `washer`, `nut`, and `bolt`, and prepares `datasets/merged/data.yaml`.

Never commit the API key. Use Colab Secrets or a runtime-only input. Do not commit the downloaded image/label directories by default; `.gitignore` intentionally excludes them.

## What is in the repo and where

**The images are not in Git**, on purpose: about 17k images across 12 sources, and two
sources are non-commercial (CC BY-NC-SA) so they should not be republished. What *is*
committed:

| What | Where |
|---|---|
| Full list of the 12 training sources (URL, licence, image count, download folder) | [`datasets/manifest.yaml`](manifest.yaml) |
| The downloader that fetches them | `host/get_model.py` (`SOURCES`), run by `train_colab.ipynb` |
| The trained model | `host/models/best.pt` |
| The first model's single dataset, "Nuts and Bolts" v1 (1,469 images) | branch `3dof-dashboard`, folder `Nuts and Bolts.v1i.yolov8/` (also on `older-working`) |

After `python host/get_model.py download` the folders are:

```
datasets/
  raw/<name>/          one per source in manifest.yaml (0428parts, mech_parts_gamal, ...)
  own/                 our own labelled photos (optional, YOLOv8 export with data.yaml)
  merged/data.yaml     generated by `merge`: washer / nut / bolt, what YOLO trains on
```

The merged `data.yaml` is generated output. Make its dataset root relocatable (relative to the generated dataset directory) rather than keeping an absolute path tied to one user's machine. Preserve class names and the train/validation/test split. Dataset files are not automatically redistributable just because they are publicly downloadable; review each dataset's terms before sharing it.
